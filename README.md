# 감상 연습장 (review-practice)

공연 · 전시 · 책 · 박람회를 보고 느낀 것을 **짧게라도 정리해 남기는** 로컬 웹앱입니다.
감상문을 바로 쓰기보다 **포착하기 → 질문하기 → 정리하기** 세 단계를 따라가며 쓸 거리를 먼저 모읍니다.

데이터베이스 없이 감상 한 편을 JSON 파일 하나로 저장합니다.

## 실행

```bash
npm install
npm start
# http://127.0.0.1:3000
```

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | 서버 포트 |
| `HOST` | `127.0.0.1` | 다른 기기에서 접속하려면 `0.0.0.0` |
| `DATA_DIR` | `./data` | 기록을 저장할 폴더 (예: 클라우드 드라이브 폴더) |

테스트: `npm test`

## 흐름

1. **홈**: **감상 남기기** 버튼, 작성 중인 감상 **이어 쓰기**, 나의 감상 목록(분류 필터)
2. **무엇을 보고 왔나요?**: 공연 / 전시 / 책 / 박람회·기타를 고르고 작품명 · 관람일 · 장소 입력
3. **작성**: 단계 탭을 오가며 자동 저장
   - **포착하기**: 해석 없이 기억나는 장면 2~3개. 분류별 힌트, 〈갈매기〉 예시
   - **질문하기**: 장면 하나를 골라 다섯 가지 질문. “슬펐다”처럼 막연한 표현에는 **‘왜?’ 한 번 더 묻기**
   - **정리하기**: 도입 · 묘사 · 감상 · 마무리 네 칸, 300자 진행 막대, 앞서 적은 **재료**를 눌러 넣기
4. **감상 읽기**: 본문, 남은 질문, 이 감상의 재료 / 수정 · Markdown 내보내기 · 삭제

## 데이터

```
data/reviews/<id>.json   # 감상 1편 = 파일 1개
```

임시 파일에 먼저 쓴 뒤 교체하는 방식으로 저장해 중간에 끊겨도 파일이 깨지지 않습니다.
`data/`는 `.gitignore`에 포함되어 있습니다.

> v1 초안의 `data/works/` 기록은 v2에서 읽지 않습니다.

## 구조

```
server.js          Express 서버와 REST API
src/content.js     분류 · 단계 · 질문 · 정리 칸 등 화면 문구
src/store.js       파일 기반 저장소
src/markdown.js    Markdown 내보내기
public/            화면 (프레임워크 없는 HTML/CSS/JS)
test/              API 테스트 (node:test)
docs/              요구사항, 디자인 목업
```

질문이나 힌트 문구를 바꾸고 싶다면 `src/content.js`만 수정하면 됩니다.
